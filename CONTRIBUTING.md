# Contributing to Tiefer

Thank you for your interest. Tiefer is an early-stage company, and our public repositories are small. Contributions are welcome, but please read this first.

## Before you start

- For anything larger than a typo, **open an issue first** and describe what you want to change and why. This saves you from building something we cannot merge.
- Security problems never go into public issues. See [SECURITY.md](SECURITY.md).

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep each pull request focused on one change.
3. Make sure the project's checks pass locally. For Go projects this usually means `gofmt`, `go vet` and `go test ./...` (see the repository's README or Makefile).
4. Describe what you changed and why, and link the related issue.

## Writing style

We keep text in our code, documentation and websites consistent:

- Plain, precise English. Short sentences.
- No emoji.
- No em dash (U+2014) or en dash (U+2013). Use commas, colons, full stops or parentheses. Our automated checks will reject them.
- No marketing superlatives and no claims we cannot back up.
